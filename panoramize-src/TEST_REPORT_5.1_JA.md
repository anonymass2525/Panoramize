# Panoramize 5.1.0 技術検証レポート

日時: 2026-11-01。Linux C++17 / CMake / Ninja のヘッドレス検証。Windows Studio One実機試験はなし。

## 新規DSP（実Native27を維持）

- Native27 VA/FM発振の能動励振に0..2xスケールを追加。波形生成・モード振動器は旧実装を使用。Native26のモード出力寄与にも0..2xスケールを追加。
- 音声スレッド上でのメモリ割り当て・ソルバー再準備なし。約5msで平滑化。モード番号0..7（対応する場合のみ）。
- 共通ID: `native51.mode.N.pickupScale` / `native51.mode.N.excitationScale`。DAW host indices: 80..95。`g51Enable`は初期無効。変化した値は`.pgraph`の新しい`NATIVE_LIVE`記録として保存できる。
- 旧Native27の音声経路はバイパスで同一（2048フレーム比較）。内部倍率有効で波形が変わることを専用テストで確認。
- 性能、複数同時インスタンス、モジュレーションのエイリアシングは広範囲で評価していない。

## リリーステスト

- Linux Release全ビルド成功。
- CTest 46件中45件合格。残りは従来の`PANORAMA_DSP`で12秒制限タイムアウト。45件を対象として再実行すると45/45合格。
- `recorded51`と専用テストの単独ASan+UBSan成功。全DSPサニタイザービルドは実行時間上限で完了せず、合格未確認。
- `.pgraph`保存・復元、壊れたLiveデータ検出、Live値と既存値の波形差: Linux C++で合格。
- Windows VST3、JUCE GUI、pluginval、Studio One未検証。

## WAV入力品質診断と識別可能性

- `recording_quality_audit.csv` はMIDI注釈付き録音のRMS/ピーク/DC/クリッピング/先頭区間RMS/周期性を記録。周期性は発音方式を証明せず、低い場合も必ずMIDI誤記とは限らない。
- `logSensitivityRank` が、張力Tと線密度μに対するf0観測のヤコビアンのランク1/2を検出。複数の観測を加えてランクが上がっても、大域的な一意性や3D逆FEMの正解は保証しない。
- CLIで生成した人工弦3テイクで、Hybrid学習損失0.0168962、未使用損失0.0194152。Pure string学習0.0196095、未使用0.0179899。人工音である。**実録音の精度検証は未実施。**
- 実録音コーパス候補としてMeta Open SoundのCC0楽器録音を案内できるが、ファイルはここで取得・測定していない。

## 依然として未達

1. 任意の未知3D形状、材質、声道構造の録音だけによる完全・一意同定。
2. Native27の全内部係数・全エンジンの全パラメーターをサンプル精度で音声スレッドへ反映。
3. 実録音（録音機材・演奏・環境の違い）での頑健性・識別精度の外部検証。
4. Windows版VST3 / Studio One / JUCE編集画面の実機安全性。

単に音が一致することは物理モデルが正しいことの証明ではない。出力の近い異なるモデル、励振条件、マイク位置、未知の材質に由来する識別限界を区別すること。
