# Panoramize 2.7.0 — 技術検証レポート

## 目標と実装結果

**目標**：複数方式が同じ型付き状態グラフに共存し、音響構造そのものをGUIで編集・保存・MIDI演奏できるようにする。旧音色の完全移植は長期目標。

**実装**：`NativeState27.h/cpp` に可変長の `Graph`（最大64モード、256結合）、`Engine`（VA/FM/Spectral/Phase/Resonance/Physical/Vocal/Nonlinear）、`Mode`（比率/減衰/非線形/集音/外力）、保存・読み込み、128 MIDIノートに対する準備済み状態ソルバー。`UniversalInstrument23` に `DirectState27` ノードを追加し、リアルタイム音声へ接続。Windows VST3の既存JUCE GUIにモード/結合編集用 `NativeGraphEditor27` を追加。

内蔵物理座標は `q [sqrt(J)*s]`, `p [sqrt(J)]`。保存結合は二次ポテンシャル、散逸結合は速度差の減衰として共通連立系へ集成。VAとFMからの波形入力は `addActiveForce` を通して外部仕事として計上する。**VA/FMのオシレーター位相まで保存的な同時連立解法へ移したわけではない。**

## 検証

- GCC Releaseビルド成功。
- CTest **16件すべて合格**（従来15件 + 新規 `Panoramize_Native27`）。
- clang++ Debug `-fsanitize=address,undefined -O1` 新規テスト通過。
- 旧2.6の実行ファイルと新2.7の実行ファイルで、代表5音色（Crystal Crown、Midnight Geometry Reforged、Tidal Alloy、Mechanical Aurora、Energy Orchard）の6.7秒ステレオ24bit WAVが**バイト単位で一致**。全72の2.6対2.7 PCM比較ではない。
- .pgraph形式の保存/復元で文字列一致・再生成音一致を確認。
- 異なるEngine/結合を持つレシピが実際に異なる音を生成。
- 不正な単位・型の結合、未完のv27グラフ読み込みを拒否するテスト合格。
- MIDIノートの発音、活性/散逸のエネルギー台帳、非有限出力の不在を確認。
- 3種類の編集可能なレシピから各5秒/48kHzステレオ16bit WAVを生成。MP3試聴では音量差を聴きやすくする処理を行い、WAVには加えない。

## 簡易CPU測定

環境: Linux GCC Release、サンプリング48kHz、8モードのデフォルトレシピ、4096フレーム（リアルタイム予算約85.33ms）。古いGUIやDAWは含まない。

| ボイス数 | 計測時間 |
|---:|---:|
| 1 | 約5.7ms |
| 4 | 約18.5ms |
| 8 | 約34.2ms |
| 16 | 約65.0ms |
| 32 | 約105.3ms |

16ボイスではCPU余裕が狭い。32ボイスではリアルタイム予算を超過。初期版はモデル演算の品質を下げる強制的な高速化はしていない。今後は負荷の高い連立演算の最適化が必要。

## 未実施・未達

- Windows MSVC/Clang Windows、JUCEコンパイル、VST3バンドル生成、pluginval Strictness 5、Studio OneのGUI操作・保存復元・リアルタイム/オフラインレンダリングは**未実行**。JUCEの新画面が動くかはWindowsビルド/実機で確認が必要。
- 今回はGUIの機能的な編集パネル。前に作成したPanoramizeの高級デザインモックを忠実に再現した完成UIではない。
- 旧72プリセットの全DSPを共通状態へ完全移植していない。Factory Sound / Legacyの旧DSPを残す互換層と、DirectState27が併存する。
- 新ソルバーの8方式は共通の**モード近似**で、完全なオリジナルVA/FM・物理弦・FEM・スペクトル処理・声帯/声道モデルの内部実装と同一ではない。真の万能合成器の完成を意味しない。
- 音響領域による全エネルギー保存則の厳密な成立は保証されない。特に能動励振、変換器、音声出力には明示した外部エネルギーが関与する。
- すべてのNATIVE27ノードが同じレシピを参照するが、個別のDirectState27ノードが別々の連立ソルバーを持つ場合、それらを一つの連立系に統合する処理は未実装。複数ネイティブノードの双方向直接作用には今後の実装が必要。
- MIDIノートごとの128ボイスを準備する設計はメモリー/CPUが大きく、一般DAWでのポリフォニック性能を保証しない。
