# PANORAMA typeGPT — Prototype 1.1.0 技術検証レポート

## 目的と変更

**テーマ：0.9/1.0の音の個性を維持しながら、型付きスペクトル状態バスの計算経路を整理する。** 今回は新規ノードやプリセットは追加せず、引き続き56プリセット。v1.0と異なるVST3識別子 `Pn11` / `com.independent.panorama.typegpt.v11` を用意した。

1. `src/FastDSPMath.h`: 12成分スペクトル系の位相演算に17次正弦近似（象限縮約＋Horner法）を導入。無制限の近似ではなく、縮約した引数を [-π/2, π/2] に収め、打ち切り誤差を極小化。
2. `MatterWeave`: Colorが固定のときに使う分散型周波数比12成分を、パッチ設定時に1回だけ前計算して全ボイスで共有。Colorがオーディオレート変調された場合は元の動的計算式を使用し、挙動を維持。
3. 一時的なスペクトルフレーム配列の全ゼロ初期化を削減。`compileGraph` と `validateModRoutes` が有効な場合は、型付き上流ノードは必ず先に全12成分を書き込んでから参照される。
4. VST3とGUIの表示を1.1.0へ更新し、独立したVST3製品識別子を設定。変更後Windows実機検証は行っていない。

## CPU測定の評価（重要）

同一Linuxホストで1.0/1.1を交互に走らせ、48kHz・0.1秒区間・4/16音の測定を試みたが、同じ条件でも時間変動が非常に大きかった。ある条件では1.1が速く、別の条件では遅く観測されたため、**高速化率を信頼できる値として提示できない**。長時間の反復測定も実行環境の時間制限に達した。

今回のキャッシュとスペクトルバス整理は実際に実装されているが、音声品質の維持が確認できた一方、**リアルタイム性能の改善および16音同時での動作達成は未証明**である。目標は大きなポリフォニーで実時間以内に収まることだが、今回の研究版をその達成品とみなしてはならない。

## 推奨するWindows検証

1. GitHub ActionsでWindows x64 Release VST3をビルド。JUCE統合スモーク、DSP CTest、pluginval Strictness 5を通す。
2. Studio Oneで1.0と1.1を別プラグインとして認識するか確認し、既存1.0プロジェクトのバックアップを保持。
3. 48kHz、128/256/512/1024サンプルブロックで4/8/16音の実測CPU・ドロップアウト・オフライン/Realtime一致を記録。
4. 1.0と1.1の同じMIDI／プリセットのWAVを録音比較し、ピーク/RMS、差分、エイリアシングを評価。
5. ピッチベンド、Mod Wheel、LFOでColorが動くMatterWeaveについて保存/再読込とノイズの有無を確認。

## 継続課題

- Windows VST3/Studio One実機検証未完。
- 16音同時発音の安定リアルタイム性能未達の可能性が高い。測定条件を固定した負荷プロファイリングとホットスポット別のアルゴリズム改善が必要。
- 非線形オシレーターのエイリアシング対策、内部音響状態バスの型拡張、GUIのノード表現は研究継続。
- 今回の正弦近似は既存の高精度数学関数との差が極めて小さいが、実効速度の向上がどのCPUでも保証されるわけではない。
