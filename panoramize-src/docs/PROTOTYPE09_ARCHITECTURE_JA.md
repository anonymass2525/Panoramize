# Prototype 0.9.0 技術設計 — Typed Spectral State Bus

## 設計の根拠

v0.8のSpectral Matterは内部で12部分音ごとに時間変動する正のエネルギー値と連続位相を持っていたが、オーディオグラフ上の下流へ伝達されるのはfloatステレオ信号だった。0.9では音声データに対して別の型を持つ**サンプル単位のスペクトル状態チャネル**を追加した。

## 実装

- `Synth::Voice::processGraph` に固定長配列（9ノード × 12成分）の`SpectralFrame`を設置。発音スレッド内・ノート内に限定し、ヒープ確保やロック、共有可変状態なし。
- `SpectralMatter`が各サンプルごとの12-partial正エネルギー分布を`SpectralFrame`へ書き込む。これとは独立にStereo Sampleも生成。
- `MatterWeave`（NodeType 17）はA/Bの**内部エネルギー分布**を読み取る。B側の逆順partialを色（COLOR）で重み付けし、ローカル12-bin reservoirへ低域通過・隣接拡散した後、連続位相で新規合成してStereo出力。次のMatterWeaveにも再伝播可能。
- スペクトル情報を持たない通常ノードをA/Bの型付き入力へ接続することはグラフ検証で拒否。Aは必須、Bは任意。
- モジュレーションは既存の2レーンのまま。既存9ノードのうち8つを自由設定し、最後の1つは固定Output。

## 数値特性

- 12エネルギー値は各ステップで0..1.7にclamp、スムージング係数は0..1の範囲、隣接拡散は非常に小さい係数で計算する。発音後の出力には既存のノード・ボイス単位のsoft clippingあり。
- ノート周波数による各部分音はNyquist以前の0.32–0.43×srの領域で滑らかに抑制。厳密なバンドリミットを保証するものではない。
- 二種の構造を混ぜた音ではなく**エネルギー分布の伝播・再構成**を実装した。これは機械的な質量・運動量保存則や厳密な音響物理モデルとは異なり、生成的な楽器用数理モデル。

## v0.8由来のJUCE上限バグ修正

`PluginProcessor.cpp`のAPVTS choice→NodeType変換ではUIインデックス15/16が必要。元コードは`jlimit(0,14,...)`で、SpectralMatter=16がPhaseEcology=15へ丸められていた。0.9では正しい`jlimit(0,16,...)`に修正。旧choice順を途中挿入せず末尾に追加、既存パラメーターIDを維持。

## 未完成の設計要件

これは全音響状態の普遍型ではない。位相ネットワーク、共鳴Q、材料剛性、衝突状態を将来の構造化バスに追加することが次の研究課題。ゼロ遅延feedbackや大規模グラフ編集は引き続きサポートしない。
